## Where the dates come from

- Lecture and exercise slots: `CMS.sessions` entries of the code (`kind` Lecture / Exercise / Tutorial / Seminar, `group` for exercise groups; `CMSUtil.attended(code)` gives the ones Bela attends). `scripts/whats_new.py` expands them with the same rules as the dashboard and flags held dates without a card.
- Course-specific calendars (OPAL calendar, chair's ICS, kick-off slides) override the weekly rule; record the result in `course.keyDates` and the item dates, and say where it came from in a `schedule.src` or note field.
- Term holidays and the Christmas break are in `CMS.term`; weekly sessions skip them automatically.

## Sources, in order of preference

1. PDFs already on disk (table above; also check `ls -t ~/Downloads/*.pdf | head` for new ones: a session that ran earlier today may have downloaded them). Read them with the Read tool, pages in chunks.
2. Decks readable in the browser (slides.com for TSP, public course websites for CV).
3. OPAL in Chrome, in a new tab of your own (other sessions share the browser; never touch or close their tabs). Bela is logged in via TUfast; never type passwords or 2FA codes. Opening a file link downloads it to `~/Downloads`: ask before doing that, and if nobody can answer (automation), list the file in the report instead.
